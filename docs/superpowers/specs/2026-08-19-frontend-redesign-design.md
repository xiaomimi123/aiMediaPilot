# 前端整体重构（十六期）

**日期:** 2026-08-19
**背景:** 用户多次反馈现有前端体验不对，本次是明确的"整体重来"请求，不是局部修补。三个具体痛点（脑暴中用户确认）：①每次打开不知道从哪入手 ②功能都在但很散落，翻好几层才找到 ③整体视觉密度太高、太乱，像后台管理系统而不是自己在用的内容创作工具。

十四期已经做过一次内容详情页的导航修补（抽屉→整页+步骤条），用户认可局部效果，但没有解决首页/侧栏层面的问题，且这次要求视觉和信息架构一起重来。本次是十四期思路的延续和放大，不是推翻重做。

## 0. 已确认决策

| 决策点 | 结论 |
|---|---|
| 问题层面 | 视觉设计 + 信息架构都要重来，不是单点修补 |
| 视觉方向 | 简洁极简（Notion/Linear 感）——大量留白、弱化装饰、用字号/灰度分层代替边框和色块 |
| 颜色基调 | **保留**现有暖色调色板（米黄纸感背景 `--paper` + 赤陶 `--clay`/橄榄绿 `--olive`/金 `--gold` 点缀色），不换成中性灰白——只降视觉密度，颜色是用户已认可、有辨识度的资产 |
| 核心工作流 | 选题 → 写脚本 → 拍/剪/发布 → 看数据复盘（线性流水线，用户确认这是实际节奏） |
| 首页结构 | 流水线首页：平台看板 ×5 + 内容总览合并成一个流水线视图（阶段列横向排开），平台变成首页内的筛选 tab，不再各自占一个侧栏入口 |
| 首页顶部 | 原"今日推进"收进首页顶部的快捷动作条（一句话总结 + 新建内容按钮），不再单独占侧栏 |
| 侧栏范围 | 从 11 项缩到 4 项：账号定位 / 灵感库选题 / 热点雷达 / 内容数据分析保留独立入口；平台看板×5 + 内容总览 + 今日推进（共 7 项）合并进新首页 |
| 改造范围 | 全站所有页面一次性换视觉样式（不是只做首页，其余页面留到以后）——包括内容详情页（十四期产物）和保留的 4 个独立侧栏页面 |
| 功能范围 | 纯视觉 + 导航结构重排，不改变任何现有功能/数据模型/API，看板拖拽换阶段等交互逻辑不变 |

## 1. 视觉设计系统

### 1.1 颜色：延续现有 token，不新增色板

`src/app/cockpit.css` 现有的 CSS 变量（`--paper`/`--surface`/`--ink`/`--muted`/`--line`/`--clay`/`--olive`/`--gold` 等，含明暗两套 `:root`/`html[data-theme="dark"]`）已经是一套完整、被 160+ 处样式规则复用的暖色调 token 系统。本次**不新增、不替换**这套变量本身，改造只发生在"怎么用这些 token"的层面——降低边框/色块的出现频率，让 `--surface`/`--paper` 之间的层次差异本身承担分区功能，而不是靠描边。

### 1.2 密度：新增间距/字号 token，全站统一收紧留白规则

新增到 `:root`（明暗两套都要加）：

```css
--space-xs: 6px;
--space-sm: 10px;
--space-md: 16px;
--space-lg: 24px;
--space-xl: 40px;
--radius-sm: 6px;
--radius-md: 8px;
--radius-lg: 12px;
--text-xs: 11px;
--text-sm: 13px;
--text-base: 14px;
--text-lg: 16px;
```

**规则**（脑暴阶段 mockup 已验证的具体数值）：
- 卡片内边距统一 `--space-md`（16px），不再各组件各写各的 padding 数值
- 卡片间距统一 `--space-sm`（10px）
- 分区标题（如"选题 · 2"）用 `--text-xs` + `letter-spacing: .05em` + `text-transform: uppercase` + `color: var(--muted)`，取代现有部分页面用粗体大字做分区标题的写法
- 边框统一走细边框 `1px solid var(--line)`，避免阴影/双层边框叠加（现有 `--shadow` 保留给需要明确"浮起"的元素，如弹层，不用于常规卡片）

### 1.3 组件基线：卡片 / 按钮 / 列表行

以脑暴阶段确认的首页 mockup 为准（见 §2），提炼出三个全站复用的基础样式类，写进 `cockpit.css`：

- `.card-minimal`：`border:1px solid var(--line); border-radius:var(--radius-md); padding:var(--space-md); background:var(--surface)`
- `.section-label`：分区标题（见上）
- 按钮沿用现有 `.primary-button`/`.secondary-button`，只调整 padding 至 `6px 14px`、字号 `--text-sm`，颜色不变（`--clay` 系）

## 2. 新首页：流水线视图

路由：`/`（替换现有首页内容；现有 `?view=platform-<x>`/`?view=pipeline` 等 query 参数路由方式保留兼容，但不再是主入口——直接跳转会重定向到新首页并预选对应平台 tab，避免旧收藏链接失效）。

### 2.1 结构（自上而下）

1. **顶部快捷动作条**（原"今日推进"内容）：一行文字总结当前待办（"你有 N 条内容卡在 X 阶段，M 条待复盘"，复用"今日推进"现有的统计逻辑，只改渲染位置和样式）+ 右侧"新建内容"按钮 + 一个"展开"控件。点击展开后，条下方原地展开出完整的日/周待办视图（复用现有 `momentum.tsx` 导出的 `DayView`/`WeekOverview`/`TodoCard` 子组件，拖拽改期等交互逻辑不变，只是从独立页面搬到首页顶部条的可折叠区域）——脑暴阶段确认："今日推进"不只是一句话总结，还有完整的日/周待办浏览+拖拽改期功能，这部分功能必须保留，用"总结+展开"而不是"简化成一句话"来承载。
2. **平台筛选 tab**：全部 / 抖音 / 小红书 / B站 / X / YouTube，横向排列，选中态用底部 2px 实线（`var(--ink)`）+ 文字色加深，未选中态 `var(--muted)`。默认选中"全部"。
3. **流水线阶段列**：横向排列，列数随平台而变——"全部"时用通用阶段集合（选题/脚本/生成成片或剪辑/发布/复盘，按 `stageFlowFor` 现有逻辑合并展示），选中具体平台时用该平台 `stageFlowFor(platform, deliveryMode)` 返回的真实阶段顺序（含十五期 `ai-faceless` 分岔——"生成成片"替代"剪辑"的逻辑直接复用，不新写）。每列顶部 `.section-label` 显示阶段名+数量，列内卡片用 `.card-minimal`，点击卡片跳转到内容详情页（十四期路由 `/content/detail/[id]`，不变）。

### 2.2 技术实现方式

不是新建路由/新数据获取路径——现有 `pipeline.tsx`/`platform.tsx`（看板视图组件）已经各自实现了"某个阶段集合 × 卡片列表"的渲染逻辑和数据来源（`loadWorkspace()`）。本次改造是：

1. 新建 `src/components/cockpit/home-pipeline.tsx`，把现有 `pipeline.tsx` 的多平台聚合数据逻辑 + `platform.tsx` 的单平台阶段列渲染逻辑，合并成一个"顶部 tab 切换平台 → 下方渲染该平台阶段列"的组件，视觉走 §1 新样式。
2. 现有 `pipeline.tsx`（`ContentOverviewView`）/`platform.tsx`（`PlatformView`）两个组件**原样保留、直接复用**——不是"保留但不再使用的死代码"，而是首页新组件 `home-pipeline.tsx` 真正的渲染载体："全部"tab 渲染 `ContentOverviewView`（不传 `platformFilter`），具体平台 tab 渲染整个 `PlatformView`（含其产出区/分发区）。真正不再被渲染的是 `momentum.tsx` 的 `MomentumView`外层包装（其内部 `DayView`/`WeekOverview`/`TodoCard` 被首页顶部条的展开区直接复用）。
3. "今日推进"现有的统计计算逻辑（`sortStageEvents`/`overdueStageEvents`，定义于 `src/lib/cockpit/workflow.ts`，零 IO 纯函数）直接复用，不重写统计口径；展开态直接复用 `momentum.tsx` 已导出的 `DayView`/`WeekOverview`/`TodoCard` 组件，不重新实现日/周待办浏览和拖拽改期。
4. 平台特定 tab（非"全部"）选中时，首页下方渲染的不只是阶段列看板，而是**整个** `PlatformView`（产出区"新建内容"按钮+能力说明、看板区、分发区三段落原样保留）——即 §2.1 的阶段列只是"全部"tab 的呈现方式；具体平台 tab 直接复用 `PlatformView` 整个组件，避免拆分其内部产出区/分发区逻辑，功能零改动。"全部"tab 则直接复用 `ContentOverviewView`（不传 `platformFilter`），与现状 `pipeline.tsx` 的调用方式完全一致。

## 3. 侧栏重排

`src/components/cockpit/sidebar.tsx` 的 `WORKBENCH_NAV_ITEMS`/`PLATFORM_NAV_ITEMS`/`OVERVIEW_NAV_ITEMS`/`ALL_NAV_ITEMS` 四个常量按下表调整：

| 现有分组 | 现有 4+5+2=11 项 | 十六期后 |
|---|---|---|
| 工作台组 | 账号定位/灵感库选题/热点雷达/今日推进 | 保留账号定位/灵感库选题/热点雷达 3 项；**今日推进从此数组移除**（内容迁移进首页顶部条，见 §2.1） |
| 创作组（平台） | 抖音/小红书/B站/X/YouTube 5 项 | **整组移除**（平台变成首页内 tab，见 §2.1） |
| 总览组 | 内容总览/内容数据分析 | 内容总览**移除**（并入首页）；内容数据分析保留 |

侧栏最终 3 组变 2 组：工作台组（账号定位/灵感库选题/热点雷达，3 项）+ 数据分析（内容数据分析，1 项），共 4 项。`MOBILE_NAV_ITEMS` 同步调整（现有逻辑是 workbench+overview，跟着上面改）。

`view-routing.ts` 里 `NavView`/`PlatformNavId` 联合类型的 `pipeline`/`platform-*`/`momentum` 几个值仍然保留（用于 `?view=` 兼容重定向的判别），只是不再出现在侧栏渲染的 `ALL_NAV_ITEMS` 里——这是"数据结构不变，展示层收窄"的改法，不是删字段，避免影响其它消费这几个 view 值判断分支的代码（如现有的移动端逻辑、深链接测试）。

## 4. 其余页面改造原则

范围内的其余页面（内容详情页 `/content/detail/[id]`、账号定位、灵感库选题、热点雷达、内容数据分析）**不改变功能和交互逻辑**，只应用 §1 的视觉基线：

- 把页面里手写的 padding/margin/字号数值，替换成 §1.2 的 token
- 把自定义边框+阴影的卡片容器，替换成 `.card-minimal`
- 分区标题统一改用 `.section-label` 样式
- 不改变这些页面的组件树结构、状态管理、数据获取方式——十四期内容详情页刚做过的"步骤条+分岔渲染"逻辑原样保留，只重新贴皮

这是一个可以逐页独立验证的机械改造（每页一个任务，视觉走查即可，不需要新写测试），跟 §2 首页的结构性改造（会新建组件、动数据聚合方式）性质不同——实施计划阶段应该分开排期，首页+侧栏是有真正设计工作量的核心任务，其余页面是应用已定基线的重复劳动。

## 5. YAGNI（不做）

- 不改变任何 API、数据模型、Prisma schema
- 不改变看板拖拽换阶段、内容详情步骤条跳转等现有交互逻辑
- 不引入新的 UI 框架/组件库，继续用现有的纯 CSS + React 组件方式
- 不做深色模式的额外设计——现有明暗两套 token 已存在，新 token（§1.2）按现有模式补齐暗色值即可，不是新设计任务
- 不做响应式断点之外的额外移动端设计打磨（`MOBILE_NAV_ITEMS` 只做结构同步，不重新设计移动端专属布局）
- 旧的 `?view=platform-<x>` 等收藏链接兼容处理保持最小化（重定向到新首页+预选 tab），不做双视图并存

## 6. 风险

| 风险 | 对策 |
|---|---|
| `momentum.tsx` 的 `MomentumView` 外层包装不再被渲染（其子组件被首页展开区直接复用），容易被误认为整个文件都是死代码 | 组件顶部加注释说明"`MomentumView` 本体不再被渲染，`DayView`/`WeekOverview`/`TodoCard` 仍被 `home-pipeline.tsx` 展开区直接复用，勿删" |
| 全站重贴皮改动面大（涉及内容详情页 1100+ 行的大文件、4 个独立侧栏页面），逐页机械替换容易漏改或误改到功能逻辑 | §4 明确"只换样式 token，不动组件树/状态逻辑"，每页改动前后做一次现有测试全绿确认+人工视觉走查，不新增测试覆盖视觉本身 |
| 首页合并平台看板逻辑（`home-pipeline.tsx`）是本次唯一有真实"新代码逻辑"的部分，容易埋结构性 bug | 复用现有 `stageFlowFor`/`loadWorkspace` 等已验证的底层函数，不重新实现阶段判定或数据获取，只重组渲染层 |
| 侧栏收窄后，`?view=momentum`/`?view=pipeline`/`?view=platform-*` 等旧链接（若被外部收藏或书签）行为改变 | §3 明确这些 `NavView` 值保留，只做"侧栏不显示 + 访问时重定向到首页并预选对应 tab"，不是访问报错 |
