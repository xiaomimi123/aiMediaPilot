# 主号文案改进设计（先问材料 → 按你的话写 → 润色 → 说话样本）

- 日期：2026-10-09
- 状态：待用户审阅
- 前置：编导写稿（`src/lib/script/write.ts`）、每日选题与实测清单（`docs/superpowers/specs/2026-10-09-daily-topics-design.md`）

## 1. 问题与目标

用户读完每日选题的初稿，觉得和自己写的差距很大：读起来不流畅、真人感差。同一主题拿用户自己写的稿子来对照（2026-10-09《Vibe Coding 两年半，我踩过的坑》）：

| | 用户写的 | 编导写的 |
|---|---|---|
| 结构 | 讲故事：我是谁 → 当时的处境 → 怎么做的 → 结果 → 经验 | 列清单：第一个坑 / 第二个坑，先说好的 / 再说崩的 |
| 细节 | 具体的东西：「自动操作浏览器上架商品的小工具」「两眼一瞪非常懵逼」 | 空话：「一个工具」「逻辑直接断」 |
| 衔接 | 像聊天 | 文章腔：「其实…」「所以结论很直接」 |
| 金句 | 从经历里长出来：「我擅长描述问题，它擅长解决问题」 | 空泛：「真门槛是会验收」 |

原因：
1. 6 段结构（开场钩子 / 概念A / 概念B / 冷知识 / 知识串联 / 金句收尾）天然写成论点清单。
2. 编导没见过用户怎么说话。
3. 讲故事需要真材料。没有材料时，模型要么编经历，要么满篇【待补】。2026-10-09 同一模型、讲故事写法的对照里，有材料的那篇明显像真人，没材料的两篇都编了经历。

目标：
- 稿子像用户本人在说话。
- 经历和数字只来自用户。
- 用户自己写的稿子能一键润色。

## 2. 已确认的决策

| 问题 | 决定 |
|---|---|
| 方向 | 先问材料 → 用户用自己的话答 → 按说话方式写 → 润色 → 存说话样本 |
| 在哪答 | 每日选题卡上直接答 |
| 润色入口 | 两处：「选题」页「我自己写了一篇」；作品「脚本」一步的「润色」按钮 |
| 润色力度 | 压到目标时长：删重复和啰嗦、调顺序、断句、改错字，不加新内容，改动全部列出 |
| 默认目标时长 | 75 秒（新作品、每日选题；每个作品可单独改） |

## 3. 写稿方式

### 3.1 结构：故事节拍

6 段不变（出片、预测、时长都按段），段名和含义改为：

| 段（键名不变） | 新名称 | 写什么 | 占比 |
|---|---|---|---|
| hook | 钩子 | 一句让人想听下去的话 | 0.10 |
| conceptA | 我是谁·当时 | 我是谁、当时在干嘛 | 0.15 |
| conceptB | 遇到什么 | 当时的处境、卡在哪 | 0.20 |
| fact | 怎么做的 | 具体过程 | 0.20 |
| bridge | 结果 | 具体的人、具体的瞬间，或干货 | 0.25 |
| close | 经验或悬念 | 一句经验，或留悬念 | 0.10 |

- 每段字数降为参考：只有全片超出目标时长上限才触发自修，单段超出只作提示。`checkDuration` 的 `ok` 改为只看全片，单段超出放进新的 `hints`。
- 已存的稿子键名不变，只是显示名变了，不需要迁移。

### 3.2 写法规矩（`write.ts` 的 SYSTEM_PROMPT）

在现有规矩上加：
- 写得像博主本人在说话，不像文章。句子长短不齐，允许口语和语气词。
- 先交代「我是谁、我当时在干嘛」，再讲事。
- 用具体的东西（具体的工具、具体的人、具体的场景），不说「一个工具」「很多用户」。
- 道理从经历里长出来，一句就够。不写「其实」「所以结论很直接」「串起来看」这类文章腔，不写空泛金句。
- 有【说话样本】时模仿它的节奏、口头说法、讲故事的方式，不照抄句子。
- 第一人称经历、测试结果、数字只能来自【用户提供的事实】或【用户的回答】，没有就写「【待补：要补什么】」（沿用现有规矩）。

### 3.3 说话样本

```prisma
/// 用户自己写的口播原文(或真实转写), 写稿时作说话样本
model VoiceSample {
  id        String   @id @default(cuid())
  title     String   @default("")
  text      String   @db.Text
  /// manual(手动加) | own_script(「我自己写了一篇」自动存) | transcript(作品转写加入)
  source    String   @default("manual")
  createdAt DateTime @default(now())
}
```

- 写稿时带最近 3 篇（按 `createdAt` 倒序），每篇截到前 800 字。
- 第一篇：用户 2026-10-09 写的《Vibe Coding 两年半，我踩过的坑》原文（验收时手动加入）。
- 设置页「说话样本」卡片：列表（标题、来源、前 60 字）、新增（标题 + 正文）、删除。
- 作品「口播」一步有转写时，加「加为说话样本」按钮（存转写全文，`source = transcript`）。

### 3.4 写稿入口

`writeScript` 增加可选参数 `samples?: string[]`、`answers?: { q: string; a: string }[]`：
- 有 `samples` 时，消息里加【说话样本】一节。
- 有 `answers` 时，加【用户的回答】一节，按「问：…／答：…」逐条列，并入事实。
- 现有调用（编导写稿工具、每日选题）都带上说话样本。

## 4. 每日选题：先问材料

- **定选题**：同时产出 `questions`（3–5 个具体问题，问能讲成故事的真事：数量、具体是哪个、哪一次、当时什么感受）。实测类的实测清单并入：每项实测也变成一个问题（「实测：<测什么>，记下：<记下什么>」）。旧数据的 `checklist` 读取时同样转成问题。
- **参考稿**：照常写一版。卡片标「参考稿」，稿里的经历全是【待补】。
- **选题卡**：列出问题，每题一个输入框（多行），旧的「实测清单」区块由它替代。答完点「按我的话写」：
  - 用 `answers` 加说话样本重写，并重新预测。
  - 卡片标签由「参考稿」变为「按你的话写的」。
  - 至少答一题才可点。
- **数据**：`DailyTopic` 增加 `questions Json @default("[]")`（字符串数组）、`answers Json?`（与问题逐项对应）；`checklist`、`results` 保留但不再写入新数据，读取时并入 `questions` / `answers`。
- **「就做这个」**：已答的问答作为一条对话消息带进作品（「你答过的材料：…」）；没答完的问题同样带进去（沿用实测清单的做法）。

## 5. 润色

### 5.1 功能

`polishScript({ llm, text, targetSec })`，返回：
- `title: string`
- `segments`：6 段，按 3.1 的节拍切分
- `changes: { kind: '删' | '挪' | '改' | '错字'; what: string }[]`：每条一句话
- `questions: string[]`：需要用户确认的地方（意思不清、前后对不上、术语观众听不懂）

规矩：
- 只用原文里的内容，不加新内容。
- 不改用户的说法和口头禅。
- 超出目标时长时删重复和啰嗦，直到不超上限。
- 改动必须全部列进 `changes`。

校验：
- **不加新内容**：润色稿里连续 12 字以上、原文里没有的片段，计入 `added`。阈值同照抄检查，复用 `findCopied` 的反向用法。页面上标「这几处是新加的，确认一下」。
- **超长**：仍超上限时自修一轮（同写稿）。

### 5.2 入口一：「选题」页「我自己写了一篇」

1. 「选题」页顶部加按钮，打开输入框（标题可选 + 正文 + 目标时长，默认 75）。
2. 点「润色」：右侧显示润色稿（6 段）、改动清单、需要确认的地方、新加的片段（如有）。
3. 两个按钮：
   - 「用润色版建作品」：建作品，脚本 = 润色稿，并跑一次稿子预测。
   - 「用原文建作品」：原文按节拍切成 6 段，不改字。
4. 原文自动存为说话样本（`source = own_script`）。

### 5.3 入口二：作品「脚本」一步的「润色」按钮

- 对当前稿子润色，弹出同样的结果面板。
- 「用润色版」：替换脚本，记一次编辑。
- 「保留原文」：关闭面板。

## 6. 出错处理

| 情况 | 处理 |
|---|---|
| 没答任何问题就点「按我的话写」 | 按钮不可点 |
| 润色 / 按回答写稿时模型不可用 | 原文、原稿不动，提示原因 |
| 润色稿出现原文没有的内容 | 标出来让用户确认，不阻止 |
| 润色后仍超时长 | 自修一轮；仍超就照样给出，标「仍超出 X 秒」 |
| 没有说话样本 | 照新规矩写，不带样本 |
| 旧选题只有实测清单 | 读取时转成问题，照常可答 |

## 7. 测试与验收

- 单元测试：
  - 新节拍名称与占比；只看全片的 `ok` 与单段 `hints`。
  - 写稿消息带上说话样本和用户回答；SYSTEM_PROMPT 含新规矩。
  - 定选题产出问题；旧实测清单转问题；「按我的话写」只用回答并重新预测；没答不可写。
  - 采用时把问答带进作品对话。
  - 润色：返回改动清单与需确认处；新加片段检测；超长自修；模型不可用保持原文。
  - 「我自己写了一篇」：建作品（润色版 / 原文），原文存为样本。
  - 脚本步「润色」替换稿子。
  - 说话样本增删、写稿取最近 3 篇。
  - 默认目标时长 75。
- 真机（会用模型额度）：
  1. 把用户的 vibe coding 原文加为第一篇样本。
  2. 用「我自己写了一篇」润色它，对比 2026-10-09 手工润色版。
  3. 对今天两个选题答两三句话，点「按我的话写」，与原初稿对比。
  4. 结果给用户评判。

## 8. 不做

- 换写稿模型：Claude 对照另议，需先在设置里加 Claude 模型。
- 语音输入回答。
- 自动从已发作品抓转写当样本：只做手动「加为说话样本」。
- 逐条接受 / 拒绝润色改动：整体用或不用，用后可手改。
