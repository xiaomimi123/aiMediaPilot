# 阶段 4 重设计：Remotion 竖屏口播成片（Claude Code 创作）

- 日期：2026-09-28
- 状态：待用户审阅
- 取代：`2026-09-27-project-agent-rebuild-design.md` 中阶段 4（特效编排 / Overlay Studio）的全部设计

## 1. 为什么改

2026-09-27 的可行性验证（真实 79 秒 U 盘口播）把 Overlay Studio 链路跑通了：编排 7.7 秒、无头导出透明层 223 秒、叠加合成 48 秒。但结论是这条路不对：

- Studio 画布写死 16:9，缩放叠到竖屏原片后卡片偏小，居中放置时章节条横穿人脸；
- 用户要的构图根本不同——**人物始终在右上角小窗，画面主体展示内容**（特效卡或用户素材），底部字幕；
- 用户明确：放弃 Overlay Studio；渲染框架选 Remotion；画面创作要由 Opus 5.5 这类强模型完成（DeepSeek 自由写画面已被实测证明偏弱）。

## 2. 已确认的决策

| 问题 | 决定 |
|---|---|
| 构图 | 1080×1920；人物小窗固定右上角全程不变；中间内容区；底部字幕 |
| 渲染框架 | Remotion（独立子工程，只出 mp4，网页端不嵌 Remotion） |
| 谁来创作 | 先在 Claude Code 里由 Opus 出片（不另计 API 费），风格定型后再接 Claude API 做网页一键出片；两者共用同一套组件库、命令行、检查规则 |
| 画面风格 | C · 极客手账：方格纸底、白色便签卡、等宽字标签、钴蓝强调色、荧光笔划重点 |
| 素材 | 录屏/视频/截图/图片；上传时可写一句说明，写了照办，没写由我看图判断；视频素材静音、放在内容区的窗口框里；比口播段长时最多 2 倍加速，仍放不下就截取最相关的一段 |
| 声音 | 口播原片原声 |
| Overlay Studio | 整套移除 |

## 3. 整体结构

| 部分 | 位置 | 职责 |
|---|---|---|
| Remotion 工程 | `remotion/`（独立 `package.json` 与 `node_modules`） | 画框组件库 `remotion/kit/` + 渲染；每条片子的源码在 `remotion/films/<项目id>-v<版本>/`（gitignore） |
| 命令行 | `npm run mp -- <命令>`（`scripts/mp.ts`） | 给 Claude Code 读写项目数据 |
| 出片 skill | `.claude/skills/produce-film/SKILL.md`（入库） | 写给 Claude 的出片流程与规矩 |
| 产品界面 | 项目页「③ 成片」标签 | 素材管理、成片版本、播放下载、素材使用表 |

出片路径：用户在 Claude Code 说"给 X 项目出片" → `mp project export` → 排镜头表 → 写内容区画面 → `film:check` → 渲染每镜关键帧并逐张看图修正 → 渲染成片 → `mp film register`。

接 API 时（后续阶段）：产品调用 Opus 执行"排镜头表 → 写画面 → 检查 → 看关键帧"，其余不变。

## 4. 画框与组件库（风格 C）

### 4.1 画布分区（1080×1920，30fps）

| 区域 | 位置 | 内容 |
|---|---|---|
| 背景 | 全屏 | `#F6F7F9` 底 + `#E3E7EE` 方格线（间距 70px） |
| 人物小窗 | 约 350×470，top 70 / right 60，圆角 36、12px 白边、投影 | 口播原片 `object-fit: cover`；裁切焦点每条片子可调（默认脸在小窗中上部） |
| 左上标题区 | x 60–650，y 70–540 | 章节标签（如 `// 笨办法.md`） |
| 内容区 | x 60–1020，y 560–1340 | 每条片子的创作只在这里 |
| 字幕带 | y 1380–1500 | `#0F172A` 圆角条、白字、最多两行；关键词可用 `#FDE68A` 荧光笔 |
| 留空区 | 底部约 20%；下半屏右侧约 120px | 抖音标题文案与点赞评论按钮会覆盖，不放重要内容 |

内容区是 `overflow: hidden` 的固定容器，任何内容都不可能压到小窗和字幕带上。

### 4.2 组件（积木）

便签卡、标签（`// xxx` 等宽字）、数字卡（钴蓝大数字 + 滚动计数）、步骤条（`01 02 03` 逐条弹入）、荧光笔、对比卡（A vs B）、引用卡、箭头/连线、窗口框（浏览器窗/手机外框，内放录屏、截图、图片；支持截取、加速、静音）、镜头转场（约 0.3 秒滑入/淡入）。

字体：苹方 + SF Mono，均为本机字体，不联网下载。

原则：组件库只提供积木和规矩；每条片子的构图、选用哪些积木、节奏由 Claude 针对内容创作——不是"往固定卡片里填字"。

## 5. 素材、成片页、命令行

### 5.1 数据（沿用 `ProjectFile`，不新建表）

| kind | 文件 | meta |
|---|---|---|
| `material` | `projects/<id>/material-<uuid>.<ext>` | `{ note, originalName, mediaType: 'image'\|'video', durationSec?, width, height }` |
| `final_mp4` | `projects/<id>/final.v<N>.mp4` | `{ filmVersion, sourceDir, usage: MaterialUsage[], summary }` |

`MaterialUsage = { materialId, atSec, durSec, clipFromSec?, clipToSec?, speed? }`

登记成片后：阶段前进到 `final`（只前进），对话里写一条 `job:film` 系统通知"成片 v<N> 已生成"。

### 5.2 「③ 成片」标签

- 素材区：拖拽上传（复用阶段 3 的流式写盘）；接受 `png/jpg/jpeg/webp` 与 `mp4/mov/m4v`；缩略图、时长、可编辑的一句说明、删除。
- 成片区：版本列表（新→旧），每版：播放器、下载、生成时间、素材使用表、这一版改了什么。
- 提示文案：修改成片请在 Claude Code 里说"改 X 项目的成片：……"（网页 DeepSeek 编导不负责出片）。

### 5.3 命令行

| 命令 | 作用 |
|---|---|
| `mp project list` | 列出项目（id、标题、阶段、是否有转写） |
| `mp project export <id>` | 打印资料包 JSON：项目、稿子、当前版本的逐句转写、口播原片绝对路径与宽高时长、素材列表（绝对路径 + 说明 + 时长）、下一个成片版本号 |
| `mp film register <id> --mp4 <路径> --usage <json> --source <目录> --summary <文字>` | 移入 mp4、建 `final_mp4` 行、推进阶段、发通知 |

## 6. 出片流程与检查（produce-film skill）

1. **读资料**：导出资料包；视频素材每 2 秒抽一帧看内容，图片直接看。
2. **镜头表** `shots.json`：按转写句子边界切成 2–8 秒的镜头；每镜写明讲什么、用卡片还是素材、素材用哪段、是否加速；首尾相接覆盖第 0 秒到原片结束。
3. **写画面**：`remotion/films/<id>-v<N>/`，只写内容区，画框/小窗/字幕由组件库接上。
4. **`film:check`**（自动）：
   - `tsc` 通过；
   - 镜头表首尾相接、不重叠、覆盖原片全长；
   - 画面文字里的每个数字都能在稿子或转写中找到（v1 教训：画面曾出现编造的价格对比表）；
   - 素材文件存在，截取区间不超出素材时长，加速 ≤ 2 倍。
5. **看关键帧**：每镜渲染一张动效完成后的静帧，逐张检查挡字、溢出、拥挤、可读性、小窗裁切；有问题改完重渲。
6. **渲染成片**：时长 = 原片全长；声音 = 原片原声。
7. **登记**：`mp film register`，附素材使用表与本版改动说明。

出错处理：渲染/检查失败 → 读报错修正重跑；素材丢失 → 跳过并在使用表与说明中注明；用户要求修改 → 出新版本，旧版保留。

### 9.1 实测（2026-09-28）

- Remotion 整片渲染：79 秒口播最简片子 114 秒；首条正式成片（15 镜 + 素材推近）117 秒；单张关键帧 3–5 秒。
- 首条成片（U 盘口播 + 店铺后台截图）：`film check` 首次报 6 条——是我把章节时间写进了 `copy.ts`，规则如实拦下；关键帧看图修了 2 处（截图太小→推近到成交数据行；买家卡说明折行）。
- 组件库待改（需用户同意）：字幕长句会折出单字孤行；数字卡对"9/10"这类比例也做滚动计数，中途会闪过"8/10"。
