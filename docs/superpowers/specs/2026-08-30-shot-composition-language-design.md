# 无人出镜画面质量：给 Builder 一套构图语言 · 设计

> 二十四期。范围限定「图文口播」与「插画配音」两条无人出镜链，真人出镜链不动。

## 一、问题

用户看完成片的原话是「效果达不到预期」，追问后指认四层全部不满意：像 PPT / 画面不动、节奏死 / 画面和文案对不上 / 文字排版不行。

### 1.1 天花板是两句写死的指令

- `director-prompt.ts`:「第一版要求构图从简：优先保证时长覆盖完整、字幕/文字清晰可读，不追求视觉丰富度和复杂运镜——用简单的文字卡片+基础过渡即可，不要设计复杂的隐喻或多层构图。」
- `builder-prompt.ts`:「第一版构图从简：文字卡片+简单几何图形+基础过渡（淡入淡出/位移）即可，不需要复杂运镜或隐喻。」

两处都是当初主动接受的取舍，写下之后没人回来改过。

### 1.2 现有「版面骨架」用的是幻灯片语汇

`facts-guard.ts` 在 high facts ≥ 2 时会下发一段版面骨架，要求「一屏至少铺 2 个信息区块」「圆角浅色卡 + 顶部小标题 + 下面几行带图标的要点」。

**实测确认：这段骨架下发了，模型也照做了。** 抽查 `ddbd3156-57b`（6 幕 / 6 条 facts / 5 条 high，条件满足），Builder 产出的最长一镜结构是：顶部小标题 + 左右两张卡（各一个标题 + 三条 bullet）+ 引用块 + 出处。

规则被 100% 遵守，产出 100% 是幻灯片 —— 因为「圆角卡 + 小标题 + 要点行」本来就是幻灯片的构件。**不是规则没被执行，是规则本身写的就是 PPT。**

### 1.3 两个否定结果（推翻了先前的假设）

**否定一：「节奏死」不是变化频率问题。** 用三种度量比对参考片与我们的成片：

| 度量方式 | 参考·PPT口播 110s | 参考·动漫讲解 240s | 我们·原版 60s |
| --- | --- | --- | --- |
| 相邻帧亮度差 > 1.5（5fps 取样） | 0.8s 一次 | 0.7s 一次 | 1.2s 一次 |
| 降到 64x36 后帧差 > 2.0（滤掉微位移） | 1.8s 一次 | 1.6s 一次 | 1.8s 一次 |
| 变化间隔分布（中位 / p90 / 最长） | 1.4s / 3.6s / **15.4s** | 1.2s / 4.0s / 6.6s | 0.2s / 3.6s / 8.0s |

三把尺子没有一把能把我们和参考片分开，参考片甚至有一段 15.4 秒不变。**所以本设计不加「变化频率」体检维度** —— 那是个会通过但没用的指标。

顺带记一个教训：第一把尺子上我们量到 0.6s、"优于"参考片，因为环境运动层让每一帧都在微动。**指标被我们自己的补丁骗了**，像素在变、信息没变。度量画面变化必须先滤掉全局微位移。

**否定二：「没有真实素材」不等于「没料可上屏」。** 参考片里体量感最强的一帧，是把 **40 条真实课程目录铺成两栏**（拆解原话「密密麻麻是故意的，用体量感说话」）。那是**文字**，不是截图。用户手上没有截图，但有六幕稿的 facts、研究简报、拆解记录 —— 这些都是可上屏的真材料，而 `ContentAsset.kind` 本来就支持 `image|table|text`。

### 1.4 现有体检查不出的真实缺陷

抽查我们成片第 20 秒的帧：顶部标题「差距不在技术，在提问」**被两张卡片压住**，「差距」二字被完全遮盖。

现有四道逐帧关（空屏 / 空壳色块 / 版面 / 文字被裁）加一道整片静止关，**没有一道查元素互相遮挡**。这是「文字排版不行」的一个可复现实例，而且可测 —— 项目已经具备读 DOM 真实几何的能力（`frame-layout.ts` 的并排检测就是这么做的）。

### 1.5 素材库有表无门

`ContentAsset` 表存在、导演也已经会主动指派 `assetIds`，但**没有任何 API 路由、没有任何前端入口**。库里仅有的 3 条是 2026-08-26 用脚本手工塞的测试数据。用户即使有素材也没有地方放，导演永远只能从一个进不去东西的空库里挑。

### 1.6 对标片校准轮（2026-08-30 补）

用户补充素材后重新拆了一轮。**结论是可用的对标片仍然只有两条**，而且拆出了三条推翻先前判断的事实。

**新增的那条用不上。** `~/Desktop/自媒体素材库/视频风格素材/13432407405416226.mp4`（1280x720 / 147s）是**真人一镜到底 + 大字叠加**，不是无人出镜纯画面片。它对 `talking-head-overlay` 链有参考价值（那条已有自己的 spec），但校准不了本期骨架。拆解库里的三条中，`002` 同样是真人出镜。所以无人出镜的可用样本是 `068`(PPT口播 111s) 与 `680`(动漫讲解 241s) 两条。

**订正一：680 有一半的画面我们的渲染器根本产不出。** 它有两种画面语域：①手绘插画场景（白发小人 + 插画机器 + 手绘物件）；②深色网格底 + 卡片 + 编号 + 绿色强调。第②种 HTML/CSS/GSAP 完全做得到，**第①种做不到** —— 我们的管线产出的是 HTML，画不出手绘角色与物件。`visualStyle: 'illustration'` 那条提示词要求「手绘感矢量插画构图」，靠 LLM 写 CSS 是永远达不到 680 那个效果的。要做到得接图像生成模型，本期不做。**所以骨架只从 068 与 680 的第②种语域推。**

**订正二（重要）：参考片同样留大片空白 —— 差别在于有常驻框架元素。** 680 第 180 秒那一帧：一张卡在左侧，右边三分之二全空 —— 和我们被批评「卡片龟缩左上」的构图一模一样。它不难看，是因为画面上有一套始终在场的框架：左上系列号 `XILO · S040`、顶部章节标签「分析结果」、卡片编号 `01`、底部字幕、背景细网格纹理。

**我们的空是真空**：没有系列号、没有章节标签、没有编号、预览阶段没有字幕（字幕是后面 ffmpeg 才烧的）、背景是纯渐变没有纹理。

这条订正推翻了 §1.2 之后我一度想加的「内容必须铺满画面」类规则 —— 那个方向是错的，会逼模型把画面塞满，正是 `frame-detail.ts` 当初防的「大色块刷分」。**正确的方向是补框架，不是填内容。**

**订正三：「亮底深字」不是通例。** 四条参考的帧均亮度：068 = 213（亮底），680 = 119，002 = 113，226 = 105。只有四分之一是亮底。上一轮拆解把它列为改动方向第一条，样本不足。本期不动色调。

## 二、不做什么

- **叙事化**（同一角色贯穿全片、三格连环画演步骤）。它和构图是两件事，一起做会失焦，排下一轮。
- **真人出镜链**（`talking-head-broll`）。它的 B-roll 会顺带受益于骨架改造，但不作为本期目标与验收对象。
- **「变化频率」体检维度**。见 §1.3 否定一。
- **重做静止检测或环境运动层**。它们已完成且验证过（三条链整片 0 静止）。

## 三、设计

三层，都落在现有管线的既有位置上。

### 3.1 素材需求声明层（新建）

**触发点：写稿定稿时**（用户选定），不是出片时。定稿时还没有分镜，所以需求从六幕稿推导。

**需求从哪来：** 六幕稿的 facts 台账。每条 `confidence === 'high'` 的 fact 就是一个天然的素材位 —— 「闲鱼AI服务卖家月均成交额不足900元」意味着画面上应该有一样能让人看出这个数的真东西。

**新表 `AssetRequest`：**

```prisma
model AssetRequest {
  id          String  @id
  userId      String
  contentId   String
  /// 需求从哪条 fact 推出来的 —— 回溯用, 也用于去重
  factClaim   String
  /// 要什么: screenshot|list|table|photo。list 是纯文字清单(参考片用 40 条真实目录铺满两栏)
  wants       String
  /// 一句话说清"要能看出什么" —— 这句话会原样显示在留白占位框里
  expectation String
  /// 必需 = 没有它这一镜只能留白; 可选 = 没有也能用构图撑住
  required    Boolean @default(false)
  /// 已补的素材。null = 还缺
  assetId     String?
  createdAt   String
  user        User    @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, contentId])
}
```

**补齐 `ContentAsset` 的进出通道**（本期必做，否则整层空转）：`POST/GET/DELETE /api/v1/content-assets`，以及写稿页上的素材需求清单区块（列出缺什么、点一下上传或粘文字）。

### 3.2 骨架层（改造，不是新建）

把 `facts-guard.ts` 里那段幻灯片语汇的 layoutBlock 换掉。新骨架**只定结构，不定样式**，且分三种，由导演按这一镜的 `visualJob` 选：

| 骨架 | 用在什么时候 | 结构契约 |
| --- | --- | --- |
| `evidence`（证据位） | 有素材位可用时。对应 visualJob = prove | 素材占画面主体（≥50% 面积），文字降为注解压在素材旁；没有第二个信息区 |
| `relation`（关系图） | 要讲 A 变成 B、A 对比 B 时。对应 compare / reveal | 左区 + 中间连接符（箭头/加号/斜杠）+ 右区。**连接符是必须的** —— 参考片正是靠它把两组东西连成一个论断，而我们只是把两张卡并排摆 |
| `volume`（体量位） | 要用"多"本身说话时。对应 clarify | 一份真实条目清单铺成 1-2 栏，条目数 ≥ 8。**允许密**，密就是内容 |

**常驻框架层（订正二新增，与三种骨架正交）。** 每一镜都必须有的、不随内容变的构件，由渲染层统一注入而不是让 Builder 每镜自己写（理由同环境运动层：凡是让模型自觉的规则都被违反过）：

| 构件 | 内容 | 位置 |
| --- | --- | --- |
| 章节标签 | 当前是六幕里的哪一幕 | 顶部左侧 |
| 镜头编号 | `03 / 08` | 卡片或主区块左上角 |
| 预览字幕 | 这一镜对应的台词 | 底部居中 |
| 背景纹理 | 极淡的网格或点阵 | 铺满 |

前三项这个项目都已经有数据（六幕结构、shotIndex、SRT），**只是没上画面**。预览阶段就要有字幕 —— 现在字幕是最后才烧的，所以预览里画面永远缺一块。

**没有素材时不许编。** 骨架里凡是标了素材位的区域，缺素材就渲染成一个**写着 `expectation` 的留白占位框**，不许用抽象色块/自造图形填满。这是把项目「界面不许撒谎」的规矩延伸到画面上：缺就是缺，看得见。

**删掉 §1.1 那两句「构图从简」**，以及 `builder-prompt.ts` 里「动画结束后画面要停在有内容的终态」这句 —— 它明说进场做完就停。

### 3.3 验收层（体检加维度）

现有四道关全在查「有没有坏」。加两道查「好不好」，两道都读 DOM 真实几何，不猜像素：

**A. 元素遮挡（`frame-overlap.ts`，新建）**
取每一镜的可见文本节点矩形，两两求交。判不合格的条件是：**文字块被其它不透明元素覆盖超过其自身面积的 15%**。阈值给宽松是因为这一维刚接上，先让它能报出来（密度阈值当初就是因为第一次标定太紧反复返工三轮）。

**B. 素材位填充率（`shot-slot-check.ts`，新建）**
一镜里声明了几个素材位、实际填了几个。**只报不拦** —— 缺素材是用户的事，不是模型的错，拦下来只会让一条本可以先看看的片子出不来。结果进成片详情页，和「画面活跃度」并排显示。

### 3.4 补素材后的重渲粒度

补齐素材后只重渲**受影响的那几镜**：复用 `direction.json` 与其余镜头已渲好的 clip，走已有的 `handleRecompose` 那条路（它现在已经会复检静止了）。不重跑导演、不重跑 Builder。

## 四、验收

本期验收靠**同一条稿子跑两遍**的对照，不靠单看一版：

1. 取 `ddbd3156-57b` 的六幕稿，按新管线重跑一遍出片。
2. 逐镜比对：新版每一镜属于哪种骨架、素材位填了几个、遮挡关有没有报警。
3. 人工看：用户判断「还像不像 PPT」。**这一条不设自动指标** —— §1.3 已经证明了自造指标会通过但没用，最终由人判断，这与参考片拆解里「相似度无法用一个数字衡量」的结论一致。

## 五、代价与风险

- **变慢**：素材位、骨架契约、两道新体检都会让 Builder 更容易第一次不达标，触发重试。现状是一条 60 秒片子纯渲染约 7 分钟（8 镜 / 30fps，不含 LLM），每镜最多 3 次 Builder 尝试。新增维度后重试率会升，最坏情况接近翻倍。
- **留白会让预览变丑**，且是故意的。用户已确认接受。
- **骨架三选一可能不够**。本期从 3 种起步，是因为参考片里能明确认出的构图模式就这几种；不够用时加第四种，而不是把三种改得越来越宽泛。
- **对标样本只有两条，且其中一条只有一半可用**（见 §1.6）。骨架从 068 全部 + 680 的深色卡片语域推出，样本量不足以分离"赛道通例"与"单个博主风格"——这个局限上一轮拆解就记过，本轮没有改善。补样本的成本很低（再下几条同类片子），但需要的是**无人出镜纯画面**形态，用户前两次提供的都不是。
- **手绘插画那条路本期封死**（680 的第①种语域）。要做到得接图像生成模型，是另一个量级的工程。`visualStyle: 'illustration'` 现在的提示词承诺了做不到的效果，本期至少应把那句话改成实话。
