# 口播文字叠加风格 —— 参考片拆解与实现规格

**参考片**: `~/Desktop/自媒体素材库/视频风格素材/13432407405416226.mp4`
**拆解日期**: 2026-08-29
**结论**: 这是一条和现有管线**假设相反**的片子, 需要新增一种交付模式。

## 一、测出来的事实

| 项 | 实测值 |
|---|---|
| 全片时长 | 147.2 秒 |
| **切镜次数** | **0**(阈值降到 0.08 仍为 0) |
| 分辨率 | 1280×720 横屏 |
| 关键词颜色 | `#1478E8` 亮蓝(采样峰值 `#1070E0`~`#1080F0`) |

## 二、机制

**全片一个机位、一个人、零切镜。所有视觉都是叠在真人画面上的文字。**

1. **人固定在右半边, 左半边留白当"白板"。** 这不是构图偶然 —— 拍摄时就把自己放在右侧, 给文字留出干净的落位区。
2. **关键词竖向堆叠 + 白色箭头**, 逐步累积成一张图解。例: `用内容 ↓ 勾住需求 ↓`; `产品 → 解决什么需求 → 内容 → 吸引什么样的粉丝`。
3. **文字分三层, 用颜色和字号区分**:
   - **蓝色关键词**(大): 结构骨架, 一屏 1~3 个
   - **白色说明**(中): 给关键词加限定, 如「解决什么需求」
   - **白色字幕**(小): 逐句跟读, 底部居中
4. **一次只出现 1~3 个文字元素**, 不堆砌。旧的会留在屏上直到这一段讲完。

## 三、为什么这条路比现在的管线更适合

现有 `talking-head-broll` 模式: 真人视频 → ASR 对齐 → Director 分镜 → Builder 出 HTML/GSAP → 无头浏览器逐帧截图 → ffmpeg 挖空替换。**三分多钟一条**, 而且 B-roll 那几段人是消失的。

参考风格不需要这里的任何一步:

- 不需要 B-roll → 不需要 Builder、不需要 Chromium 渲染
- 不需要挖空 → 人一直在
- **所有叠加都能编译成一个 `.ass` 文件**, 和字幕一起一次烧录

ASS 原生支持这里需要的全部能力: `\pos()` 绝对定位、`\an` 对齐锚点、`\fs` 字号、`\c` 颜色、`\fad` 淡入淡出、逐条事件的起止时间。**一条 147 秒的片子几秒钟出**, 不是三分钟。

## 四、实现

新交付模式 `talking-head-overlay`。

**管线**: 真人视频 → ASR 转写 → LLM 出「叠加计划」→ 编译成 `.ass` → 一次 ffmpeg 烧录。

**叠加计划**的元素只有三种(对应上面测到的三层), 位置用**语义槽位**而不是让模型给像素 —— 模型给不准像素, 而槽位可以由我们保证不压到人脸:

- `keyword` 蓝色关键词
- `note` 白色说明
- `arrow` 白色箭头(连接上下两个元素)

**槽位**: 画面左半边纵向 5 格(`left-1` ~ `left-5`)、顶部居中、底部居中。人在右半边是这个风格的拍摄前提, 所以左半边永远是安全区。

**常驻声明**独立配置(模板级), 不进 LLM 计划 —— 它每条片子都一样, 让模型每次重写只会引入不一致。

## 五、这条规格没覆盖的

- 参考片里的箭头是**图形**不是文字。ASS 能画矢量(`\p1` 绘图模式), 第一版先用字符 `↓`/`→` 顶替, 效果差在箭头细一些。
- 参考片的人物构图靠**拍摄时就站在右边**。系统不做人像分割/移位 —— 那需要 matting, 是另一个量级的工程。规格里明写: **这个风格要求你录的时候人在右半边**。
