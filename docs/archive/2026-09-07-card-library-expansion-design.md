# 卡片库扩容：五张数据/实体卡 · 设计

> 三十三期。范围：把卡片库从 4 张扩到 9 张，新增圆环比例、翻牌计数、增长曲线、排名条、人物名牌。参考 [overlay-studio](https://github.com/jeszhou/overlay-studio) 的同类卡片（**学视觉构成与动效手法，不搬实现**——它是 CSS transition + rAF 双时钟，我们是 Remotion 按 frame 的纯函数）。

## 一、为什么做

### 1.1 用户实机反馈（2026-09-06）

三十二期交付实时预览后，用户上手第一句是「动效的话只有几种可以选择的」。追问确认包含两层意思：动效换不了、**卡片种类太少**。三十二期 spec §九已记录这条推翻。

### 1.2 现有四张卡的表达力缺口

`statement` / `stat` / `contrast` / `list` 覆盖的是「一句话 / 一个数 / 两组对比 / 一份清单」。知识类口播里高频出现、但现在只能硬塞进这四张的内容：

| 内容形态 | 现在只能 | 缺的卡 |
| --- | --- | --- |
| 一个比例（占比 32.2%、完成度 78%） | `stat` 从 0 数上去，看不出「占整体多少」 | 圆环比例 |
| 一个大数的量级感（累计 11000 单） | `stat` 平滑滚动，缺机械계数的分量 | 翻牌计数 |
| 一段时间的增长（三年涨了三倍） | 只能写成 `statement` 文字 | 增长曲线 |
| 多项排名（前五名分别是…） | `list` 只有条目、没有量的对比 | 排名条 |
| 锚定某人/某机构（DeepSeek 拿了 74 亿融资） | `statement` 里混着讲 | 人物名牌 |

**`stat` 只有「从 0 数到 N」一种呈现**，而数字在知识类内容里的语义至少有四种：绝对量、比例、变化趋势、排名。一种呈现服务四种语义，是当前最实的缺口。

### 1.3 顺序决定（用户拍板 2026-09-07）

三件事（扩卡片库 / 预览上拖文字 / 换进场动效）中，**先扩卡**。用户理由是新卡面马上能用上，而另两件是「已有的东西更好用」。

**代价与对冲**：先扩卡意味着新卡写的时候还没有拖动与动效切换机制，将来接入时可能返工。对冲办法是**新卡按「将来要能拖、要能换动效」的结构写**（见 §四），使下一期是接线而不是重写。

## 二、五张卡的设计

每张卡的槽位遵循既有填槽契约：模型只选卡 + 填字，不碰坐标/颜色/动效参数。

### 2.1 `ring`（圆环比例）

- **视觉**：纵向居中——小标签 → 320px 见方的圆环（轨道 + 进度环，12 点起画）+ 环心大数字与单位 → 说明文字
- **槽位**：`label`(≤16) / `value`(number) / `max`(number，默认 100) / `unit`(≤6，可选) / `note`(≤24，可选)
- **动效**：环用 `stroke-dasharray` + `dashoffset` 生长，环心数字同步从 0 数上去——**共用同一个进度值**（原项目是 CSS 1100ms 与 JS 1100ms 两套时钟手动对齐，我们一个 `interpolate` 驱动两者，天然同步）
- **什么时候用**：这一镜的重点是「占比 / 完成度 / 达成率」这类**有分母**的数。没有分母就用 `stat`

### 2.2 `odometer`（翻牌计数）

- **视觉**：纵向居中——小标签 → 逐位数字滚轮（每位一个高度固定的窗口，内含 0-9 纵列）+ 单位 → 说明文字
- **槽位**：`label`(≤16) / `value`(整数) / `unit`(≤6，可选) / `note`(≤24，可选)
- **动效**：每位数字从 0 滚到目标位，**个位先停、逐位向高位延迟**（机械计数器的观感）。原项目是 CSS transition 一次性跳到终值（观感上「划过」但本质只有起终两态），我们**做成真实的逐帧连续滚动**——Remotion 下这反而更简单
- **什么时候用**：数字本身的**量级**是重点（累计、总量、里程碑），且是整数。带小数或有分母的用 `stat` / `ring`

### 2.3 `curve`（增长曲线）

- **视觉**：卡片内——左上小标签（英文/中文两行）+ 右上峰值大数字；中间曲线图（平滑曲线 + 下方渐变面积 + 每个数据点的圆点与上下标注）；底部可选出处小字
- **槽位**：`label`(≤16) / `points`(3~8 项，每项 `{at: ≤8字, value: number}`) / `unit`(≤6，可选) / `note`(≤24，可选出处)
- **动效**（这张卡的核心资产，照抄的是判断不是代码）：
  - 曲线用 SVG `pathLength=1` 归一化 + `dashoffset` 描画——**与真实像素长度解耦**，进度值直接就是「画了多长」
  - **一个进度值 `draw` 串起三件事**：曲线描画、面积透明度、数据点逐个亮起（`on = clamp((draw - at) / 0.15)`，曲线画到哪点就亮到哪）
  - 峰值数字比曲线**晚 300ms 收尾**——曲线画完时数字刚好停住，是有意的节奏
  - 平滑曲线用 Catmull-Rom → 三次贝塞尔转换（纯几何函数，可直接复用）
- **什么时候用**：讲「随时间变化」的叙事（增长、下降、波动）。只有首尾两个数、不讲过程的用 `contrast`

### 2.4 `rank`（排名条）

- **视觉**：纵向列表，每行是「名称 + 数值」一行、下方一条进度条；最高值那行用强调色，其余降调
- **槽位**：`title`(≤16) / `rows`(2~6 项，每项 `{name: ≤12字, value: number}`) / `suffix`(≤6，可选单位)
- **动效**：条形 `scaleX` 从 0 生长（左对齐原点），数值同时滚动；**逐行错峰**（每行延迟 0.14s）。原项目条形 900ms、数字 1400ms **故意不对齐**——条先到位、数字还在滚，保留这个错落
- **什么时候用**：多项之间**比大小**（排名、份额、对比多方）。只列举不比较的用 `list`

### 2.5 `entity`（人物名牌）

- **视觉**：横向排 1~3 块名牌，每块两行（主名 + 可选副行：机构/头衔/英文）；浅色牌与深色牌两种皮肤；右侧可选两行小注
- **槽位**：`chips`(1~3 项，每项 `{name: ≤12字, sub?: ≤16字, tone: 'light'|'dark'}`) / `note`(≤20，可选)
- **动效**：每块从左滑入 + 淡入，**逐块错峰**（默认 0.5s 间隔），**进场后常驻不退场**（这是「锚定」型卡片的语义）
- **什么时候用**：需要**点名具体的人或机构**（引用来源、提到某公司/某人）。泛指的主体不用这张
- **注意**：名牌是实心色块，卡片全局的文字阴影在其上会显脏——需单独去掉（原项目专门为此加了 `text-shadow: none`）

## 三、模型选卡（用户拍板：模型照选，剪辑台可换）

新卡**全部进提示词**，模型自主判断用哪张；用户在剪辑台不满意再换。

**已知风险**：卡多了模型可能乱选。二十七期实测过同类现象——卡片描述写不好，模型会扁向某一张（当时是全塞进 `statement`，靠给每张写「什么时候用」才纠正）。所以：

- 每张新卡的说明必须写**什么时候用 + 什么时候不用**（§2 各卡末尾那句就是原型）
- 界线要**可判定**，不能是「视情况」：`ring` 与 `stat` 的界线是「有没有分母」、`curve` 与 `contrast` 的界线是「讲不讲过程」、`rank` 与 `list` 的界线是「比不比大小」
- **本期必须做一轮选卡分布实测**（三条真实稿子各跑 3 遍，看九张卡的实际分布）——这是二十七期定下的做法：改提示词必须有前后对比数据，不许凭感觉

## 四、为下一期留的结构（不实现，只留位）

下一期做「预览上拖文字」与「换进场动效」，本期的新卡按这两件事的需求写：

1. **文字块打标记**：每个独立文字块渲染时带 `data-slot="<槽位名>"`（如 `data-slot="label"`、`data-slot="row-2-name"`）。下一期的拖拽层靠它定位——`<Player>` 不用 iframe（三十二期核实过：它是同文档内 `transform: scale()`），外层能 `querySelector` 到。
2. **动效走 anim 函数**：新卡的进场一律调用 `motion/anim.ts` 的纯函数（或按同样形状新增），**不在卡片里内联写动画逻辑**。下一期加「换动效」时才能把函数换掉。
3. **重复结构的可拖粒度**：`rank` 的每一行、`curve` 的每个数据点是天然的可拖单元——渲染时按行/按点包一层带标记的容器，不要把数字与名称拆到无法整体移动。

## 五、不做什么

- **不做拖动、不做动效切换**（下一期）
- **不做常驻层**（章节进度条、要点钉板——那要改 FilmPlan 结构加独立于 shots 的 overlays 数组，另开一期）
- **不搬 overlay-studio 的参数编码方式**：它把多行数据编码成 `"名称,数值|名称,数值"` 字符串（因为它的面板只有单个 textarea 控件），我们直接用结构化数组
- **不搬它的绝对定位锚点系统**（九宫格 + CSS 变量偏移）：我们的卡是 flex/栅格，这是既定差异
- **不给新卡加 style 之外的新参数**：三十二期的 speed/accent/scale 对新卡同样适用，不为单张卡开小灶

## 六、测试

- 每张新卡一条**真渲染**测试：给定槽位渲一帧，断言画面非空且关键像素符合预期（如 `ring` 的环所在位置有非背景像素）
- 动效的**分阶段**断言：`curve` 在 draw=0.5 时，前半段的数据点已亮、后半段未亮（用两个时刻抽帧比像素）
- `odometer` 的逐位错峰：某一帧上个位已停、十位还在动
- 卡片注册表一致性（既有 `card-registry.test.ts` 扩展）：schema 里九种卡都有实现、都有文件
- **选卡分布实测**（§三）：三条稿子 × 3 遍，记录九张卡的分布，与四卡时代对比

## 七、风险

- **模型选卡扁向**（§三已述，用实测数据兜）
- **新卡的槽位校验**：`points`/`rows`/`chips` 是结构化数组，`.strict()` 下每个元素的字段也要校验；模型填错的错误信息必须精准（二十七期教训：`z.union` 的并列报错让模型放弃整张卡，本项目已统一用 `discriminatedUnion`，新卡照此）
- **一次加五张卡的工作量**：每张 = 组件 + schema + 卡片说明 + 真渲染测试。若实施中发现单期过重，**按 §2 的顺序砍尾部**（`entity` 最简单可最后做，`curve` 最复杂但价值最高应优先）——砍的决定要记在案，不要默默少做
